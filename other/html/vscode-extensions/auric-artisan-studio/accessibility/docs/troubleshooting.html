Auric Accessibility troubleshooting

Symptoms, causes and fixes for Auric Accessibility's diagnostics, Inspect, scans and Project Issues view.

For problems shared by all Studio extensions (scans, the data folder, settings), see the Studio troubleshooting page.

Diagnostics

No WCAG underlines appear

Why: One of these applies:

  • the file's language is not one the rules check; plain .js and .ts files get contrast checks only, not markup rules;
  • VS Code does not recognise the file type (for example Svelte or Astro without their language extension), so the language is plain text;
  • auricA11y.a11y.enabled is off;
  • the file is larger than 1 MB;
  • a suppression directive such as auric-disable-file covers it.

What to do: Check the language in the status bar's language picker, install the language's extension if needed, and check the setting and any auric-disable comments. See Editor linting.

A rule does not fire where I expect

Why: The profile excludes its criterion (for example target size needs the 2.2 profile), the value is supplied at runtime and is treated as unknown, the tag is a component rather than a native element, or the markup is generated by JavaScript.

What to do: Check your profile in Audit profiles and contrast, and see What the rules cannot judge.

A finding looks wrong

Why: Static checks cannot see everything, for example a label added by a component or text set at runtime.

What to do: If the markup is correct, silence that rule on that line with Ignore here or auric-disable-next-line <rule-id>, ideally with a comment saying why. See Suppression and branding.

A best-practice hint is not in the Problems list

Why: Best-practice findings are hints, which VS Code shows as dotted underlines and may hide from the Problems panel depending on your filters.

What to do: Check the Problems panel's filter, or view them in the Studio's Findings tool.

Apply fix added "Describe this field"

Why: Some fixes add a placeholder label so the control has a name at all.

What to do: Replace the placeholder with a real, specific label. See Apply fix.

The ignore comment appears as text on the page

Why: Inside JSX markup, a // comment inserted by the quick fix is JSX text.

What to do: Change it to {/* auric-disable-next-line … */}.

Inspect

Hovering shows nothing, or the colour card instead of Inspect

Why: The cursor is on a colour value (the colour card wins), on a line with a finding (the finding's card wins), on an element Inspect does not consider meaningful (such as a plain div with no role, label or finding), or inspect.onHover is off.

What to do: Press Ctrl + Alt + A with the cursor inside the element, or move to its tag name.

The command says "place the cursor inside an element, a CSS rule, or a style region"

Why: Nothing inspectable surrounds the cursor, for example in a CSS file outside any rule.

What to do: Move the cursor inside an element or a { … } block.

Inspect shows "via file colors"

Why: The element has no colours of its own in this file, so Inspect shows the file's most used pair as an example.

What to do: Treat the contrast as indicative only; check the real styles in the browser.

Scans and the Project Issues view

"Scan Project" reports old results

Why: A fresh cache was reused (the message says (cached)).

What to do: Use Force Rescan Project and Refresh Cache.

The Project Issues view only says "Run a project scan"

Why: There is no scan result yet, or the cache was cleared.

What to do: Select Run a project scan.

The Project Issues view lists code-health findings, but there are no code-health underlines

Why: Project scans always include the code-health checks; editor underlines for them come from Auric Code Health.

What to do: Install Auric Code Health if you want them in the editor. With Auric Code Health installed, you can also leave them out of scans by turning off auricCodeHealth.codeHealth.enabled.

Search found nothing

Why: The search matches text in each row; it is not a pattern language.

What to do: Try a shorter word, a criterion number or a file name. Select Filtered by "…" to clear.

The badge number differs from the Problems panel

Why: The badge counts every finding in the project from the last scan; the Problems panel shows only open files.
