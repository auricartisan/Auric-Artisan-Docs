# Glossary

**Activity Bar** — the vertical strip of icons at the side of the VS Code window. Some extensions add their own icon there.

**Application scope** — a setting that can only be set in user settings and applies to every window.

**Command Palette** — the searchable list of every command, opened with `Ctrl` + `Shift` + `P`.

**Extension ID** — the unique name of an extension, in the form `publisher.name`, for example `auric-artisan.auric-artisan-live`.

**Extension pack** — an extension with no features of its own that installs a list of other extensions.

**Extensions view** — the VS Code panel for searching, installing and managing extensions, opened with `Ctrl` + `Shift` + `X`.

**Fork** — an editor built from the VS Code source code, such as Cursor, Windsurf or VSCodium.

**Launcher** — the `code` command (or a fork's equivalent) that opens VS Code and manages extensions from a terminal.

**Marketplace** — the Visual Studio Marketplace, the gallery where the Auric Artisan extensions are published.

**Open VSX** — a separate, open extension gallery used by many forks. The Auric Artisan extensions are not published there.

**Profile** — a named VS Code setup with its own extensions and settings.

**Project file** — a configuration file kept in the repository, such as `auric.live.json` or `.auricformatrc`, that an extension reads for that project.

**Resource scope** — a setting that can be set for the user, the workspace, or a single folder of a multi-root workspace.

**Restricted Mode** — the state VS Code runs in when you have not trusted a folder. Extensions can limit themselves in it.

**Settings Sync** — the VS Code feature that copies settings and the list of installed extensions between machines through your account.

**Virtual workspace** — a folder opened from a remote source without a local copy on disk.

**VSIX file** — the package file for a VS Code extension, ending in `.vsix`.

**Window scope** — a setting that can be set in user or workspace settings.

**Workspace settings** — settings stored in the open folder's `.vscode/settings.json` or in a `.code-workspace` file, applying only to that workspace.

**Workspace trust** — your decision, per folder, about whether VS Code and extensions may run code and read configuration from it.
