==============================================================================
AUDIT RULES
==============================================================================
Every rule in the extension's accessibility engine, grouped by category, with
its impact, WCAG 2.2 success criteria and whether the audit runs it.
Area: Browser extension › Check   Updated: 2026-09-25

The accessibility engine behind Audit and Findings has 80 rules in eight
categories, mapped to 32 WCAG 2.2 success criteria. The audit runs at level
AA, so it applies the 78 rules that test levels A and AA. The two AAA rules,
enhanced text contrast (1.4.6) and reduced motion (2.3.3), are part of the
engine but are not run by the audit.

The engine uses the WCAG 2.2 success criteria, the ARIA 1.2 role and attribute
definitions and the HTML accessibility mappings bundled in the extension, so
questions such as "is this attribute allowed on this role" are answered from
the specifications rather than guessed. Accessible names are computed with the
standard accessible-name algorithm, following `aria-labelledby`, labels,
`title` and content.

IMPACT
======

Each finding has an impact, the same scale most accessibility tools use:

  Impact   | Meaning
  ---------+-------------------------------------------------
  critical | Blocks some people from using the content at all
  serious  | A significant barrier; fix soon
  moderate | Makes the content harder to use
  minor    | A nuisance or a best-practice gap

A finding is either a failure or a warning. A warning means a person must
decide, for example contrast over an image.

HOW THE SCORE IS CALCULATED
===========================

The score, from 0 to 100, counts distinct failing rules, not each failing
element, so one unlabelled button repeated down a long table is one problem to
fix. Each failing rule costs points by impact (critical 10, serious 6,
moderate 3, minor 1), multiplied by 1 plus the base-10 logarithm of how many
times it failed. For example, one critical rule failing on 10 elements costs
10 × 2 = 20 points. Warnings never lower the score. The score appears in the
JSON export.

RULES
=====

The ID is how each rule appears in an exported JSON report. "Page" rules check
the document once; the others check each matching element.

Keyboard (8)
------------

  ID:     `tabindex-positive`
  Rule:   Positive tabindex overrides the natural focus order
  Impact: serious
  WCAG:   2.4.3

  ID:     `interactive-not-focusable`
  Rule:   Element behaves as a control but cannot be focused
  Impact: critical
  WCAG:   2.1.1

  Rule:   Focus indicator is removed by a stylesheet
  Impact: serious
  WCAG:   2.4.7 (AA)

  ID:     `target-size-minimum` (page)
  Rule:   Touch target is smaller than 24 × 24 px
  Impact: serious
  WCAG:   2.5.8 (AA)

  ID:     `accesskey-duplicate` (page)
  Rule:   `accesskey` value is used more than once
  Impact: moderate
  WCAG:   2.1.1

  ID:     `focusable-hidden-offscreen`
  Rule:   Off-screen element is still in the tab order
  Impact: moderate
  WCAG:   2.4.3, 2.4.7

  ID:     `autofocus-used`
  Rule:   `autofocus` moves focus on page load
  Impact: minor
  WCAG:   2.4.3

  ID:     `nested-interactive`
  Rule:   Interactive element nested inside another
  Impact: serious
  WCAG:   4.1.2

`interactive-not-focusable` understands "roving tabindex": a composite widget
such as a tab list passes when one of its items holds the Tab stop.
`target-size-minimum` respects WCAG's spacing exception for small targets that
are well separated.

Contrast (4)
------------

  ID:     `color-contrast`
  Rule:   Text contrast is below the AA threshold
  Impact: serious
  WCAG:   1.4.3 (AA)

  ID:     `color-contrast-enhanced`
  Rule:   Text contrast is below the AAA threshold (not run by the audit)
  Impact: moderate
  WCAG:   1.4.6 (AAA)

  ID:     `non-text-contrast`
  Rule:   Control boundary has insufficient contrast
  Impact: serious
  WCAG:   1.4.11 (AA)

  ID:     `link-distinguishable`
  Rule:   Link in text is identified by colour alone
  Impact: serious
  WCAG:   1.4.1

Text over an image or gradient is reported as a warning for manual review, not
a failure. Checkboxes and radio buttons drawn by the browser are exempt from
`non-text-contrast`, as WCAG allows.
